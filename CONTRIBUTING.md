# Contributing

Use Rust 1.95+ and run the five checks in README.md. Ordinary tests need loopback socket access but no Kalshi credentials. Never add private keys, account dumps or production-order tests. Tests generate signing keys in memory.

Handwritten code lives in `src/auth.rs`, `client.rs`, `error.rs`, `fixed.rs` and `websocket.rs`. `models.rs`, `rest.rs`, `websocket_models.rs`, `websocket_messages.rs` and the REST coverage table are generated by `tools/generate.py` from the pinned JSON specs. Change the generator instead of patching generated Rust. Regenerate and format, then ensure a second generation produces no differences.

For spec changes, keep Predictions and Perps separate, record the upstream version and hashes in spec/README.md, review breaking changes and update meaningful fixtures. Response requiredness, nullability, numeric representations, query arrays, authentication and no-body responses need particular attention. Do not hide model drift by defaulting all response fields or turning structured responses into generic JSON.

Optional integration tests remain ignored, Demo-only, and order submission requires the explicit opt-in in README.md. Do not run every ignored test merely to read an account. Check generated Rustdoc examples and all runnable examples after any API change.
